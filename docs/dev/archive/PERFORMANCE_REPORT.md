# Qwen3.5-Thor — 性能测试报告

> 测试平台: NVIDIA Jetson AGX Thor (SM110a Blackwell)
> CPU: 14-core Arm Neoverse V3AE @ 2601 MHz
> 内存: 128 GB LPDDR5X, 峰值带宽 273 GB/s
> GPU: 20 SM, 2560 CUDA Cores, 32 MB L2 Cache
> 功耗模式: MAXN (130W)
> 测试日期: 2026-03-09

---

## 1. 支持的模型

| 模型 | 参数量 | 精度 | 权重大小 | 架构 |
|------|--------|------|----------|------|
| Qwen3.5-4B | 4B | BF16 | ~8.4 GB | Dense (24层, 12 LA + 4 FA + 8 LL) |
| Qwen3.5-9B | 9B | BF16 | ~15.9 GB | Dense (48层, 36 LA + 12 FA) |
| Qwen3.5-27B | 27B | BF16 | ~51.3 GB | Dense (64层, 48 LA + 16 FA) |
| Qwen3.5-27B-NVFP4 | 27B | FP4+BF16 | ~18.4 GB | Dense (64层, NVFP4 MLP) |
| Qwen3.5-35B-A3B | 35B (3B active) | BF16 | ~67 GB | MoE (48层, 256 experts, top-8) |
| Qwen3.5-122B-A10B-NVFP4 | 122B (10B active) | FP4+BF16 | ~83 GB | MoE (48层, 256 experts, top-8, NVFP4) |

> LA = Linear Attention (Gated DeltaNet SSM), FA = Full Attention (GQA + Paged KV Cache)
> LL = Linear Layer (无 attention, 仅 MLP, 4B 模型特有)

## 3. MTP 投机解码性能 (Multi-Token Prediction)

### 3.1 测试方法

- 通过 serve 模式启动服务器，使用 Ollama API 发送请求
- 每个 d 值测试 2 个 prompt (中文 + 英文)，各生成 500 tokens
- 采样参数: temperature=0.7, top_p=0.8, top_k=20, presence_penalty=1.5

## 5. 关键发现

### 5.1 MTP 接受率与模型规模

- **小模型 (4B)**: d=2 最优，draft 质量高，小 d 已收敛
- **中型模型 (9B, 27B)**: d=3 最优，更大搜索空间带来更高接受率
- **大型 MoE 模型 (35B, 122B)**: d=2 最优，MoE 路由增加预测不确定性

### 5.2 NVFP4 量化对 MTP 的影响

- NVFP4 量化降低了 MTP draft 的接受率
- 27B BF16 最优 d=3，而 27B NVFP4 最优 d=2
- 122B NVFP4 MoE d=3 即严重退化，最大安全 d 仅为 2

### 5.3 d=5 退化现象

- Dense 模型 (27B BF16, 27B NVFP4) 在 d=5 时英文输出出现重复退化
- MoE 模型 (35B) d=5 仍稳定但速度低于基线
- 推测: 高 d 值时多层 SSM state 回滚频繁，state 漂移较大

### 5.4 MTP 速度提升上限

- 理论最大提升: (d+1)× (完美接受率)
- 实测最大提升: 27B BF16 d=3 → +128% ≈ 2.28×, 接近理论 4× 的 57%
- MTP verify 额外开销 (multi-row GEMV, KV/SSM write) 限制了实际收益

| cache_enabled | true | true |
| cache_ssm_state | true | true |

### 6.3 稳定性评估

- MaxRepeat30: 输出文本中 30 字符滑窗的最大重复次数
- PASS: MR ≤ 3 (允许自然重复如标点、代码模式)
- FAIL: MR > 3 (出现文本退化/重复)
- 每个 d 值测试 2 个 prompt (中文编程题 + 英文科学分析), 各 500 tokens
