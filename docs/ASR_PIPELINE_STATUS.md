# ASR V4 Pipeline 实现总结与优化方向

> **最后更新**: 2026-03-16  
> **当前版本**: V4 Phase 6 + Phase 3b (commit `2028212`)

---

## 一、V4 Pipeline 架构

```
┌─────────────────────────────────────────────────────────────┐
│                     V4 ASR Pipeline                         │
│                                                             │
│  Phase 1: 音频 → VAD 分段 → ASR 逐段转写 → 全文拼接          │
│                                                             │
│  Phase 2: ForcedAligner → 字级时间戳 (CTCAlign)              │
│                                                             │
│  Phase 3: Fine-grained VAD + CAM++ → 说话人嵌入 → 聚类       │
│                                                             │
│  Phase 3b: 碎片吸收聚类 → 4人 (从7人)                         │
│                                                             │
│  Phase 4: 时间戳 × 说话人标签 → 每字 speaker 分配             │
│           (3-tier: exact → overlap → nearest)               │
│                                                             │
│  Phase 5: 按 speaker 连续段生成 segments                     │
│                                                             │
│  Phase 6: 全文标点恢复 → 字级对齐 → 说话人重分段              │
│                                                             │
└─────────────────────────────────────────────────────────────┐
```

### 关键组件

| 组件 | 模型/方法 | 说明 |
|------|-----------|------|
| ASR | Qwen3-ASR-1.7B | 原生 C++/CUDA 推理 |
| ForcedAligner | CTC forced alignment | Python 子进程, 字级时间戳 |
| VAD | SileroVAD (ONNX) | 精细语音段检测 |
| 说话人编码 | CAM++ (GPU) | 192维 L2-normalized embedding |
| 说话人聚类 | SpeakerManager | 贪心匹配 (cos_sim≥0.65) + Phase 3b 碎片吸收 |
| 标点恢复 | PunctuationRestorer | 规则引擎 (select_clause_end) |

## 二、优化历程

### Phase 6: 全文标点恢复 (commit `6c4b3e6`)

**问题**: 独立段标点导致跨段断句 24 处, 段尾标点率仅 93%

**方案**: 
1. 拼接全部 word 为单一文本
2. 一次性标点恢复
3. 字符级对齐回 word 时间戳
4. 按说话人连续段 + 句号边界重新分段

**结果**:
- 段尾标点: 93% → **100%**
- 跨段断句: 24 → **0**
- 碎句: 15 → 11

### Phase 3b: 碎片吸收聚类 (commit `2028212`)

**问题**: 7 个说话人, 实际仅 3-4 人; 凝聚聚类过度合并 (Speaker_0+1 sim=0.801 合并导致 100s+ 巨段)

**方案**: 碎片吸收策略 (fragment absorption)
- 确立说话人: seen ≥ 5 (保护, 绝不互相合并)
- 碎片说话人: seen < 5 (吸收到最近确立说话人, cos_sim ≥ 0.55)
- 避免两个确立说话人合并

**诊断数据** (pairwise cosine similarity):
```
Speaker_0↔Speaker_1: 0.801 (seen 59,14) → 都是确立, 保留独立 ✓
Speaker_0↔Speaker_2: 0.579 (seen 59,3)  → 碎片吸收到 Speaker_0 ✓
Speaker_3↔Speaker_4: 0.646 (seen 9,1)   → 碎片吸收到 Speaker_3 ✓
Speaker_3↔Speaker_5: 0.557 (seen 9,1)   → 碎片吸收到 Speaker_3 ✓
Speaker_6: sim < 0 everywhere            → 保留独立 (噪声)
```

**结果**:
- 说话人: 7 → **4**
- 碎句: 11 → **0**
- 段落: 29 → **22**
- 段尾标点、跨段断句维持 100%/0

## 四、优化方向分析

### 方向 A: 句内标点质量提升 (影响: ★★★★★, 难度: ★★★★)

**现状**: 规则引擎 `PunctuationRestorer` 基于简单启发式 (字数阈值 + 标点词典), 存在:
- 不合理断句: "景春的。身份就已经被" (应为逗号)
- 独白式口语难以准确分句: "他一直没死一直往后拖一直往后拖就导致发生改变了"

**方案选项**:

| 方案 | 优点 | 缺点 |
|------|------|------|
| A1: LLM 后处理标点 | 质量最高, 理解语义 | 推理延迟大, 需 Qwen3.5 调用 |
| A2: 专用标点模型 | 精度高, 延迟可控 | 需额外模型 (CT-Transformer/BERT) |
| A3: 改进规则引擎 | 零延迟, 零内存 | 上限低, 难以处理复杂句式 |
| A4: ASR 端到端标点 | 最优方案, 一步到位 | 需模型支持 (Qwen3-ASR 当前不支持) |

**建议**: **A2 (专用标点模型)** — 用轻量 BERT-based 标点模型 (~100MB), 在 GPU 上推理, 延迟 <50ms, 质量接近 A1。可复用 Jetson GPU 算力。

### 方向 B: 说话人分离精度 (影响: ★★★★, 难度: ★★★)

**现状**: 
- Speaker_3 (1段, 8.7s) 存疑 — 可能是噪声或真实短插话
- 跨段说话人切换处有语义连续但 speaker 不同的情况 (Seg 8→9)
- 初始聚类阈值 0.65 固定, 未适配不同音频场景

**方案选项**:

| 方案 | 说明 |
|------|------|
| B1: 自适应聚类阈值 | 基于总说话人数/分布动态调整 identify 阈值 |
| B2: 重叠检测 | 多人同时说话时分离 (当前只取一个) |
| B3: 说话人嵌入长度优化 | 当前取整个 VAD 段平均, 可改为中间稳定段 |
| B4: 时序约束 | 利用说话人切换频率的先验 (不会 1s 内连续切换) |

**建议**: **B4 (时序约束)** — 后处理阶段加入说话人平滑: 短于 N 秒的 speaker island 合并到前后主说话人。成本最低, 效果明确。

### 方向 C: 长段拆分 (影响: ★★★, 难度: ★★)

**现状**: 5 个段落 >60s, 最长 86.2s。一个段落内 4+ 句话, 阅读体验差。

**方案**: 在 Phase 6 重分段时, 除了在说话人切换点分段, 也在同一说话人内按句号分段(当累计时长 >30s 时)。

**建议**: 简单阈值即可, 在现有 Phase 6 循环中加 `if (seg_duration > max_seg_seconds) split at 句号`。

### 方向 D: 口语规范化 (影响: ★★★, 难度: ★★★★)

**现状**: 忠实转写包含大量口语冗余:
- 重复: "梁平死了梁平死了梁平死了"
- 语气词: "嗯嗯", "对不对", "哈"
- 不完整句: "就是就是说"

**方案选项**:
- D1: 规则去重 (连续相同 n-gram 合并)
- D2: LLM 口语规范化 (Qwen3.5 post-process, 最高质量但延迟大)
- D3: 保留原文 + 提供 "clean" 版本 (API 参数控制)

**建议**: **D3** — 默认忠实转写, API 可选 `clean=true` 触发规则去重。不改变默认行为。

### 方向 E: 端到端延迟优化 (影响: ★★, 难度: ★★★)

**现状**: 748s 音频的完整 V4 pipeline 处理时间 ~120s+ (ASR 70s + Aligner 20s + CAM++ 30s)

**方案**: 
- E1: ASR 和 CAM++ 并行执行
- E2: ForcedAligner 批处理优化
- E3: 去掉 ForcedAligner 依赖 (ASR 直接出时间戳)

### 优先级排序

```
C (长段拆分) > B4 (时序平滑) > A2 (标点模型) > D3 (口语规范化) > E (延迟优化)
  [★★ 难度]     [★★★ 难度]     [★★★★ 难度]      [★★★★ 难度]      [★★★ 难度]
  [立即可做]     [半天实现]      [需新模型]         [API 设计]        [架构调整]
```
